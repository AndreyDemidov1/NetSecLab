# NetSecLab

NetSecLab — интерактивный тренажёр по анализу сетевых атак и защитных механизмов. Проект предназначен для безопасной учебной симуляции DoS-атак и демонстрации способов их нейтрализации в локальной среде.

Приложение не выполняет реальные атаки на сеть. Основной поток представлен логическими пакетами-объектами в памяти приложения. Это позволяет изучать поведение сетевого трафика, включать защиту и сразу видеть результат без риска для реальных узлов и сетевого оборудования.

## Текущий этап разработки

На текущем этапе реализованы базовое Avalonia-приложение, модуль генерации атак, модуль защитных механизмов и журнал логических пакетов.

Пользователь может настроить тип атаки, целевой IP, порт и интенсивность, запустить генерацию логического трафика, включить защитные механизмы и наблюдать, какие пакеты были пропущены, защищены или заблокированы.

## Реализованные возможности

- Запускаемое кроссплатформенное Avalonia-приложение.
- Общий слой `NetSecLab.Core` с моделями, событиями и интерфейсами.
- Инфраструктура `NetSecLab.Infrastructure` с DI-регистрацией и шиной событий.
- Отдельный модуль генерации атак `NetSecLab.Modules.Attacks`.
- Отдельный модуль защитных механизмов `NetSecLab.Modules.Defense`.
- Генерация логических пакетов для атак:
  - SYN-flood;
  - UDP-flood;
  - ICMP-flood;
  - HTTP Slowloris.
- Добавление фонового трафика для более реалистичной симуляции.
- Настройка целевого IP, порта и интенсивности генерации.
- Остановка атаки в любой момент.
- Отображение логических пакетов в таблице.
- Расчёт текущей скорости потока пакетов.
- Расчёт количества нейтрализованных пакетов.
- Расчёт эффективности защиты.

## Модуль защитных механизмов

Модуль защиты анализирует каждый логический пакет перед отображением в журнале и принимает решение о его состоянии:

- `Пропущен` — пакет не нарушает активные правила защиты;
- `Защищён` — пакет обработан защитным механизмом без полного блокирования;
- `Заблокирован` — пакет отброшен выбранным правилом защиты.

На текущем этапе реализованы следующие защитные механизмы:

- **SYN cookies** — срабатывают при подозрительно высокой частоте TCP SYN-пакетов и помечают такие пакеты как защищённые.
- **Rate limiting** — ограничивает количество однотипных пакетов в секунду и блокирует пакеты после превышения заданного лимита.
- **Поведенческий фильтр** — блокирует пакеты, похожие на HTTP Slowloris, по признаку частичных HTTP-заголовков.
- **Blacklist** — блокирует все пакеты от IP-адресов, добавленных в чёрный список.
- **Whitelist** — при включении пропускает только IP-адреса из белого списка, если список не пуст.

Blacklist и whitelist применяются к IP-адресу источника и проверяются раньше остальных правил защиты. Это соответствует логике списков доступа: если источник явно запрещён или не входит в список доверенных, дальнейшая проверка пакета уже не требуется.

В интерфейсе для списков доступа предусмотрены поля ввода IP, кнопки добавления, удаления одного IP и полной очистки списка. Поля и кнопки становятся недоступными, если соответствующий механизм защиты выключен. Ввод IP ограничен диапазонами, которые реально используются генератором логического трафика.

## Структура решения

```text
src/
├─ NetSecLab.App                # Avalonia-приложение и пользовательский интерфейс
├─ NetSecLab.Core               # Общие модели, события, настройки и интерфейсы
├─ NetSecLab.Infrastructure     # DI, шина событий и резервные сервисы
├─ NetSecLab.Modules.Attacks    # Модуль генерации логических атак
└─ NetSecLab.Modules.Defense    # Модуль защитных механизмов
```

## Принцип интеграции модулей

Модули не связаны напрямую друг с другом. Они подключаются через общий слой `NetSecLab.Core`, регистрируются через DI-контейнер и обмениваются событиями через `IEventBus`.

Такой подход позволяет развивать проект поэтапно: добавлять новые атаки, защитные механизмы, сценарии, отчёты и визуализацию без полной переработки уже существующего кода.

## Запуск

Для запуска требуется установленный .NET 8 SDK.

```bash
cd src/NetSecLab.App
dotnet restore
dotnet run
```

Или на Windows из корня проекта:

```bat
start.bat
```
