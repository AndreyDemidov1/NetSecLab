# NetSecLab

NetSecLab — интерактивный тренажёр по анализу сетевых атак и защитных механизмов. Проект предназначен для безопасной учебной симуляции DoS-атак и демонстрации способов их нейтрализации в локальной среде.

Приложение не выполняет реальные атаки на сеть. Основной поток представлен логическими пакетами-объектами в памяти приложения. Это позволяет изучать поведение сетевого трафика, включать защиту и сразу видеть результат без риска для реальных узлов и сетевого оборудования.

## Текущий этап разработки

На текущем этапе реализованы базовое Avalonia-приложение, модуль генерации атак, модуль защитных механизмов, стохастическое ядро симуляции, модуль визуализации в реальном времени, журнал логических пакетов и базовый модуль учебных сценариев.

Пользователь может выбрать учебный сценарий, настроить тип атаки, целевой IP, порт и интенсивность, запустить генерацию логического трафика, включить защитные механизмы и получить оценку своих действий по нескольким критериям.

## Модуль защитных механизмов

Модуль защиты анализирует каждый логический пакет перед отображением в журнале и принимает решение о его состоянии:

- `Пропущен` — пакет не нарушает активные правила защиты;
- `Защищён` — пакет обработан защитным механизмом без полного блокирования;
- `Заблокирован` — пакет отброшен выбранным правилом защиты.

На текущем этапе реализованы следующие защитные механизмы:

- **SYN cookies** — срабатывают при подозрительно высокой частоте TCP SYN-пакетов и помечают такие пакеты как защищённые.
- **Rate limiting** — ограничивает количество однотипных пакетов в секунду и блокирует пакеты после превышения заданного лимита.
- **Поведенческий фильтр** — блокирует пакеты, похожие на HTTP Slowloris, по признаку частичных HTTP-заголовков.
- **Blacklist** — блокирует все пакеты от IP-адресов, добавленных в чёрный список.
- **Whitelist** — при включении пропускает только IP-адреса из белого списка, если список не пуст.

Blacklist и whitelist применяются к IP-адресу источника и проверяются раньше остальных правил защиты. Это соответствует логике списков доступа: если источник явно запрещён или не входит в список доверенных, дальнейшая проверка пакета уже не требуется.

В интерфейсе для списков доступа предусмотрены поля ввода IP, кнопки добавления, удаления одного IP и полной очистки списка. Поля и кнопки становятся недоступными, если соответствующий механизм защиты выключен. Ввод IP ограничен диапазонами, которые реально используются генератором логического трафика.

## Модуль визуализации в реальном времени

Модуль `NetSecLab.Modules.Visualization` отвечает за подготовку данных для наглядного отображения хода симуляции. Он получает результаты проверки пакетов и формирует компактные снимки текущего состояния трафика.

В текущей реализации визуализация показывает:

- динамику трафика за последние 12 секунд;
- соотношение атакующего и фонового потока;
- распределение пакетов по протоколам TCP, UDP, ICMP и HTTP;
- распределение решений защиты: пропущено, защищено и заблокировано.

Визуализация не заменяет журнал пакетов, а дополняет его: таблица показывает подробности каждого логического пакета, а графические блоки позволяют быстро увидеть общую картину атаки и реакцию защиты.

Шкала динамики трафика не пересчитывается вниз во время активной сессии, поэтому график не меняет масштаб при каждом обновлении. Распределения протоколов и решений отображаются как процентные индикаторы от 0 до 100%, чтобы разница между 60%, 80% и 100% была визуально заметной.

## Модуль учебных сценариев

Модуль сценариев задаёт пользователю учебную задачу и оценивает выполнение не только по факту включения защиты, но и по нескольким характеристикам:

- **время реакции** — насколько быстро после начала атаки был включён подходящий механизм защиты;
- **правильность выбора** — соответствует ли выбранный тип атаки и защитный механизм условию сценария;
- **эффективность** — какой процент пакетов был нейтрализован защитой;
- **адаптивность** — использовал ли пользователь комбинирование защит и менял ли конфигурацию после запуска атаки.

На текущем этапе добавлены сценарии с одиночными и комбинированными механизмами защиты:

- SYN-flood: SYN cookies + rate limiting;
- UDP-flood: rate limiting + blacklist;
- Slowloris: поведенческий фильтр + whitelist;
- ICMP-flood: whitelist.

Адаптивность оценивается не только по факту изменения защитных механизмов после запуска атаки, но и по реакции на случайные события стохастической модели: всплески атаки, смену IP-адреса атакующего, увеличение фонового трафика и кратковременные провалы связи.

Интерфейс сценария расположен первым в левой панели, потому что сценарий задаёт общий порядок работы: сначала выбирается учебная задача, затем настраиваются генератор атаки и защитные механизмы.

## Стохастическое ядро симуляции

Модуль `NetSecLab.Modules.Simulation` отвечает за вариативность поведения симуляции. Он не создаёт реальные сетевые пакеты, а управляет логическим потоком, который создаётся генератором атак.

В текущей реализации стохастическое ядро выполняет несколько задач:

- рассчитывает количество атакующих пакетов на каждом шаге симуляции с учётом базовой интенсивности и гауссова шума;
- формирует фоновый трафик по вероятностной модели;
- создаёт случайные события во время атаки:
  - всплеск интенсивности атаки;
  - всплеск легитимного фонового трафика;
  - временная смена IP-адреса атакующего;
  - кратковременная нестабильность соединения;
- передаёт события в интерфейс, чтобы пользователь видел, почему поток изменился;
- рассчитывает коэффициент нагрузки, который влияет на вероятность успешного срабатывания некоторых защитных механизмов.

Blacklist и whitelist остаются детерминированными: если IP попадает под правило списка доступа, пакет блокируется независимо от нагрузки. SYN cookies, rate limiting и поведенческий фильтр могут временно работать менее эффективно при высокой нагрузке, что делает сценарии ближе к учебной модели из технического задания.

## Структура решения

```text
src/
├─ NetSecLab.App                # Avalonia-приложение и пользовательский интерфейс
├─ NetSecLab.Core               # Общие модели, события, настройки и интерфейсы
├─ NetSecLab.Infrastructure     # DI, шина событий и резервные сервисы
├─ NetSecLab.Modules.Attacks    # Модуль генерации логических атак
├─ NetSecLab.Modules.Defense    # Модуль защитных механизмов
├─ NetSecLab.Modules.Scenarios     # Модуль учебных сценариев и оценки
├─ NetSecLab.Modules.Simulation    # Стохастическое ядро симуляции
└─ NetSecLab.Modules.Visualization # Визуализация в реальном времени
```

## Принцип интеграции модулей

Модули не связаны напрямую друг с другом. Они подключаются через общий слой `NetSecLab.Core`, регистрируются через DI-контейнер и обмениваются событиями через `IEventBus`.

Такой подход позволяет развивать проект поэтапно: добавлять новые атаки, защитные механизмы, сценарии, отчёты и визуализацию без полной переработки уже существующего кода.

## Запуск

Для запуска требуется установленный .NET 8 SDK.

```bash
cd src/NetSecLab.App
dotnet restore
dotnet run
```

Или на Windows из корня проекта:

```bat
start.bat
```

## Ограничения текущей версии

На текущем этапе проект реализует логическую симуляцию атак, базовую реакцию защитных механизмов, стохастическое ядро и систему учебных сценариев с оценкой действий пользователя. PDF-отчёты, история сессий, профиль пользователя, SQLite-хранилище и консоль псевдокоманд относятся к следующим этапам развития проекта.

Ближайшие следующие технические этапы — отчёты по сессиям, более подробная история прохождения сценариев, настройки пользователя и расширенный анализ трафика.
